| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 主流程 | 报修人在文博1首层选位置，开门观察，新建报修并选真实PNG/JPEG；管理员从该位置事项进入审核，主动选合格人；维修人接单、独立进度、本轮新结果/凭证；原人验收 | 灰蓝待审核→红色待接/处理中→蓝色待验收→只移本事项；原申请只计一次；无台账不影响闭环 |
| 台账兼容 | 有关联台账工单按原显式设备接口建立后从空间列表处理 | 原位置/材料/身份可追溯；台账与无台账各自合法；不为正常首次派单加设备必选 |
| 同位置隔离 | 两报修人同101报修，分别登录观察；管理员核对 | 各看本人数量/颜色/事项/按钮/图片，管理员看完整范围；一条完成不清其余 |
| 补充位置 | 管理员退回101申请；原人在补充页改到另一首层位置但先不提交，再提交 | 草稿不改变提示；成功后迁移原申请，编号/首次时间不变，旧位置其他事项仍在 |
| 撤回/重复 | 原人撤回待审/待补充；管理员核实具体台账带原因重复关闭 | 原历史保留，当前空间只移对应申请，公共空间不开放报修 |
| 拒单/改派 | 原维修人带原因拒单，管理员人工重派；另单接前换人 | 待重派红色不计原人当前空间；新负责人可见；原人仅从普通列表查本人有限历史，无后续新图 |
| 返工 | 原报修人第一轮不通过带原因；原维修人第二轮提交新图/新结果后通过 | 同工单/实际维修人/首次acceptedAt；普通处理中与返工互斥，旧轮图不能作新轮凭证 |
| 实时同步 | 独立Cookie主机管理员/报修人/当前维修人相互观察 | 正常联网、前台他人改变≤30秒；本人已确认写入立即重读；导航数量继续独立30秒口径 |
| 刷新故障 | 隔离页阻断读取8秒、断网/恢复、后台/恢复 | 有权旧数据标过期/上次成功/重试，失败不推进成功时间；首次失败不显示空成功，恢复即时读取 |
| 编辑保护 | 一端编辑时另一端改变状态；换身份时旧响应迟到 | 字段/File保留但旧提交禁用，确定失去查看权才清相应编辑及ObjectURL；旧账号响应不覆盖新账号 |
| 写入UNKNOWN | 隔离页在已收到200的响应阶段丢弃写响应，核对原结果/原标识重试 | 原operationId/完整payload冻结，事件数仍1；只清本用户/资源/操作/轮次草稿 |
| 导航与布局 | 单条标识→详情，多条标识→事项选择→详情→返回；键盘、320px、减少动态、3D失败 | 点击提示无提交/上传，不默认操作第一条；保留位置/楼层/观察/事项页；顶侧栏与下方业务区可用 |
